# Warframe State Graph — テキストDSL仕様（ChatGPT等に渡す用）

Warframe State Graph（個人用の依存グラフ完了トラッカー）の「テキストから一括生成」機能で読み込めるDSLの仕様です。ChatGPTなどのAIチャットにこのファイルの内容を貼り付けて、「〜のノードを書いて」と頼めば、そのままアプリに貼り付けられるDSLテキストを生成させられます。

同じ内容が「テキストから一括生成」モーダル内の「AI用の説明をコピー」ボタン（`ts/web/dsl-help.ts`）にも入っています。どちらかを直したらもう片方も直してください。

## 構文

トークンはこの4種類だけです。

- `A -> B` : 「Aの前提（requires）はB」。矢印は連鎖できる（`A -> B -> C`）。
- `A -> [B -> C]` : 「Aの中身（contains）にB」。角括弧の中でも`->`は同じ意味（requires）で、入れ子にもできる（`[B -> [C]]`）。
- `,` : 複数の式（チェーン）区切り。1回のテキストにいくつでも書ける。
- ノード名 : 日本語・英語どちらも可。スラグ化されず、書いた文字列がそのままノードのidになる。

## 意味・ルール

1. **同じ名前は同一ノードに統合される**。テキスト中に同じ名前が何度出てきても1つのノードとして扱われる（前提/中身は合算される）。既存のグラフに同名ノードが既にある場合は、そのノードを**丸ごと上書き**する（マージではない）ので注意。
2. **括弧は「直前のノード」の中身に繋がる**。`A -> [B -> C] -> D`は、「Aの中身にB」「BはCが前提」「AはDも前提」の意味——括弧の後ろの`-> D`はAから続く（Bの続きではない）。
3. **他のどこからも参照されない名前（＝チェーンの先頭）だけが探索起点（Goal）になる**。それ以外はすべて他ノードのrequires/containsから辿ってたどり着く末端・中間ノード。
4. 空の括弧`[]`や、閉じ括弧の欠落はエラーになる。
5. 自己参照（`A -> A`）は無視される（エッジは作られない）。

## 例

**単純な前提チェーン**
```
Mag Prime入手 -> Neuroticsレリック開封 -> Neo N1レリック周回
```

**パーツ構成（中身＋各パーツの前提）**
```
Mag Prime -> [設計図 -> Lithレリック開封], Mag Prime -> [シャーシ -> Mesoレリック開封], Mag Prime -> [ニューロティック -> Neoレリック開封], Mag Prime -> [システム -> Axiレリック開封]
```
（「Mag Prime」を4回書いているが、同一ノードに統合され、中身に4パーツ全部がまとまる）

**同名ノードの共有（クエストチェーンなど）**
```
二番目の夢 -> Natah, 内なる紛争 -> 二番目の夢
```
